# A2.1 — `ms(value, options)` — SHORT

**Library:** [`ms`](https://www.npmjs.com/package/ms) v2.1.3
**Source read:** `node_modules/ms/index.js` (162 lines) and `node_modules/ms/README.md`
**Chosen because (short):** it is in this project's tree transitively via `debug` and
`send`, and its output type is two-valued in a way that is easy to get wrong at a call
site: `parse` returns `undefined` while the top level throws.

**Provenance:** the brief asks for a first pass without AI. This was written by an AI,
so that requirement is not met and is not claimed. The comparison against a
general-knowledge account of each function is in `ai-comparison.md`; where the two
disagree, the harness settles it.

## Pseudocode

```
FUNCTION ms(value, options)
INPUTS:
  value (text or number) — either a string to PARSE into milliseconds ("2h", "1.5d")
                 or a number of milliseconds to FORMAT back into a human string
  options (object, optional) — `long` (boolean). Only consulted on the format path.
                 Defaults to an empty object
OUTPUT: a number, when it parsed a string;
        a text string, when it formatted a number;
        or it THROWS. It never returns nothing — the failure mode is an exception,
        except for the private `parse` helper, which returns nothing (undefined)
SIDE EFFECTS: NONE
FAILS WHEN:
  - value is not a non-empty text string AND not a finite number — THROWS
    Error("val is not a non-empty string or a valid number. val=" + JSON.stringify(value))
  - called with only one argument that is neither a string nor a number
  It does NOT throw for a malformed string like "5 apples" — that returns nothing
  (undefined) from the private parser, which the top level then RETURNS AS-IS.
  That asymmetry (throw for a bad type, undefined for bad content) is the detail
  that makes this function worth reading.
```

### Steps

1. SET `options` to the second argument if one was given, OTHERWISE to an empty object.
2. SET `type` to the kind of value: text, number, or something else.
3. IF `type` is text AND `value.length` is greater than 0
   RETURN the result of the private parser, whatever it produces — including nothing.
4. OTHERWISE IF `type` is number AND the number is finite (not `Infinity`, not `NaN`)
   RETURN the formatted text: the long form if `options.long` is truthy, otherwise the
   short form.
5. OTHERWISE THROW an Error whose message names the offending value, serialised as
   JSON so the reader can see its actual type.

**The private parser (`parse`), which step 3 delegates to:**

```
FUNCTION parse(text)
INPUTS: text (text) — the string to interpret
OUTPUT: a number of milliseconds, OR nothing (undefined) if the string is not
        a recognised duration
SIDE EFFECTS: NONE
FAILS WHEN: never throws. It reports every failure by returning nothing.
  1. IF the text is longer than 100 characters, RETURN nothing immediately.
     This is a length guard so the regular expression below cannot be handed an
     arbitrarily long string.
  2. MATCH the text against this pattern, case-insensitively, anchored at both ends:
     an optional minus sign, then digits which may be empty, then an optional
     decimal point, then digits; then any number of spaces; then an OPTIONAL unit
     word. If there is no match, RETURN nothing.
  3. SET `n` to the matched number parsed as a decimal.
  4. SET `type` to the matched unit lowercased, OR to the text "ms" if no unit was
     present. A bare number therefore means milliseconds.
  5. MULTIPLY `n` by the constant for its unit and return that:
     year / years / yrs / yr / y   -> multiply by 365.25 days
     week / weeks / w               -> multiply by 7 days
     day / days / d                 -> multiply by 24 hours
     hour / hours / hrs / hr / h    -> multiply by 60 minutes
     minute / minutes / mins / min / m -> multiply by 60 seconds
     second / seconds / secs / sec / s -> multiply by 1000
     millisecond / milliseconds / msecs / msec / ms -> return `n` unchanged
     any other unit (unreachable, because the pattern only allows the above)
       -> RETURN nothing
```

**The private formatters, which step 4 delegates to:**

```
FUNCTION formatShort(ms)
INPUTS: ms (number) — a number of milliseconds, possibly negative
OUTPUT: text — the largest whole unit that the magnitude fits into, suffixed with
        its abbreviation, e.g. "2d", "3h", "5m", "9s", "42ms"
STEPS:
  1. SET magnitude to the absolute value of ms.
  2. IF magnitude is at least one day, RETURN the number of whole days rounded,
     suffixed "d".
  3. OTHERWISE IF at least one hour, RETURN whole hours rounded, suffixed "h".
  4. OTHERWISE IF at least one minute, RETURN whole minutes rounded, suffixed "m".
  5. OTHERWISE IF at least one second, RETURN whole seconds rounded, suffixed "s".
  6. OTHERWISE RETURN the original number with no suffix, as text.

FUNCTION formatLong(ms)
INPUTS: ms (number) — milliseconds, possibly negative
OUTPUT: text — the same unit choice as the short form, but spelled out and
        pluralised
STEPS:
  1-5. IDENTICAL unit selection to formatShort: compare the ABSOLUTE value against
     day, hour, minute, second, in that order. (Note: this is why "1 day" and
     "25 hours" both format as hours-or-days by magnitude, not by exactness.)
  6. OTHERWISE RETURN the original number followed by " ms".
  7. FOR the chosen unit, PLURALISE the name only when the magnitude is at least
     one and a half times the unit. So 1 day is "1 day" but 1.5 days is "2 days".
```

## Hand traces

Traced by hand from the source above, then executed against the real library.
`ms` is CJS, so the harness uses `createRequire`.

### Input 1 — NORMAL. Parse a duration string

**Given:** `ms("2h")`

| Step | What happens | Value |
|---|---|---|
| 1 | `options` = `{}` | — |
| 2 | `typeof "2h"` | `"string"` |
| 3 | length 3 > 0, and it is a string | call `parse("2h")` |
| p1 | length 3 ≤ 100 | continue |
| p2 | pattern matches: number `2`, unit `h` | — |
| p3 | `n = 2` | `2` |
| p4 | unit `"h"` lowercased | `"h"` |
| p5 | `2 × 3,600,000` | `7200000` |
| 3 | return the parser's result | **`7200000`** |

**Expected:** the number `7200000` (two hours in milliseconds). ✓

### Input 2 — EDGE. A bare number string means milliseconds, and a
too-long string returns nothing without touching the regex

**Given:** `ms("250")`, and separately `ms("x".repeat(101))`

For `"250"`:
| Step | What happens | Value |
|---|---|---|
| p2 | pattern matches: number `250`, **no unit captured** | — |
| p4 | `match[2]` is absent, so the default is used | `type = "ms"` |
| p5 | milliseconds branch returns `n` unchanged | `250` |

**Expected:** `250`. The "no unit means milliseconds" default is the kind of default
that silently turns a typo into a 250-millisecond timeout.

For the 101-character string:
| Step | What happens | Value |
|---|---|---|
| p1 | length 101 > 100 | **RETURN nothing** |
| p2-5 | never reached | — |

**Expected:** `undefined`, not a throw, and notably the regex is never executed.
The point of the guard is bounded work, not a friendlier message.

### Input 3 — INVALID. A number that is not finite

**Given:** `ms(Infinity)`

| Step | What happens | Value |
|---|---|---|
| 2 | `typeof Infinity` | `"number"` |
| 4 | is `Infinity` finite? **no** | branch not taken |
| 5 | neither branch applied | **THROW** |

**Expected:** an `Error` whose message ends `...val=null` when serialised — because
`JSON.stringify(Infinity)` is the text `null`. So the error message is actively
misleading: it says `val=null` for an argument that was `Infinity`. That is a small
real bug in the library, and it is only visible by tracing what `JSON.stringify`
does to a non-finite number. `ms(NaN)` behaves identically.

**Bonus probe:** `ms("5 apples")` does **not** throw. The pattern fails to match, the
parser returns nothing, and step 3 returns that nothing. So the same library answers
a bad *type* with an exception and a bad *value* with `undefined` — and a caller
doing `ms(userInput)` gets `undefined` with no signal at all.
